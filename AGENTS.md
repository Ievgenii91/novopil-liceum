# AGENTS.md — Novopil Lyceum website

Official public website of **Новопільський ліцей Оліївської сільської ради** (a rural public school in Zhytomyr oblast, Ukraine).
Static site generated by a **zero-dependency Node.js script** from Markdown/JSON in `content/`, with a Git-based CMS (Decap) and a custom local visual editor.

This file is the always-loaded entry point. Read the topic docs below when your task touches that area.

## Commands

`node` is **not** on PATH on the maintainer's Windows machine — use the wrapper `.\node.cmd`. `git` may also be missing from PATH.

```powershell
.\node.cmd src/build.js     # build content/ + public/ -> dist/   (npm run build)
.\node.cmd src/server.js    # build, then serve http://localhost:3000 + CMS API (npm start) — long-running
```

- There are **no tests, no linter, no `node_modules`**. Verification = run the build, read its console summary (page/news counts), and inspect the generated HTML in `dist/`.
- CI (`.github/workflows/deploy.yml`) runs `node src/build.js` on Node **20** and deploys `dist/` to GitHub Pages on push to `main`.

## Non-negotiable rules

1. **Zero dependencies.** Do not add npm packages, bundlers, frameworks, or a `node_modules` folder. Use only Node built-ins (`fs`, `path`, `http`, `child_process`). Code must run on Node 20.
2. **Edit sources, never `dist/`.** `dist/` is generated (and committed). After changing `content/`, `public/`, or `src/`, rebuild so `dist/` stays in sync. The build does **not** delete stale output — if you rename/remove a page, delete its old `dist/<path>/` folder too.
3. **Ukrainian only** for all user-facing text (UI strings, content, alt text, SEO descriptions, CMS labels). Code comments in this repo are also in Ukrainian; match the surrounding style.
4. **Never invent official facts.** Legal requisites (ЄДРПОУ, КАТОТТГ, ІСУО ID), names, phone numbers, emails, student counts, document URLs and legal citations must come from existing repo data or the user. If something is unknown, leave a clearly marked placeholder and tell the user.
5. **Single source of truth is imperfect.** School contact data lives in `content/settings/site.json` **and** is hardcoded in several places in `src/build.js` (sidebar, hero, topbar, footer, contacts widget) and in page Markdown. When changing any such fact, search the whole repo (`content/`, `src/`, `README.md`) and update every occurrence.
6. **Respect the custom parsers.** Frontmatter and Markdown are parsed by hand-written regex code in `src/build.js`, not real YAML/CommonMark. Write content in the supported subset (see content-authoring.md) — e.g. single-line frontmatter values, inline arrays, no Markdown images with alt text.
7. **Accessibility is a legal requirement** (WCAG 2.1 / ДСТУ ISO/IEC 40500:2015). Any markup/CSS change must keep the a11y panel themes, font scaling, labels, alt text and keyboard access working.
8. **Keep the four config surfaces in sync** when adding a content type, page section, or field: `src/build.js`, `src/server.js` (`/api/content/list`), `public/admin/config.yml` (Decap), and `README.md` sitemap.
9. **Don't silently "fix" deployment URLs** (absolute `/` paths, sitemap domain `novopil-lyceum.zt.ua`, Decap `backend.repo`). Flag inconsistencies to the user instead.
10. Use **UTF-8** for every file read/write. In PowerShell pass `-Encoding UTF8`; otherwise Cyrillic text turns into mojibake.
